# 系统可靠性与回归验证

模型配置和工具权限在写入成功后才更新运行状态。配置、会话、任务、知识库索引和工具权限采用同目录临时文件替换，保留 `.bak` 上一版本；主文件无法解析时会尝试读取上一版本。任务写入异步合并，保存失败会显示错误，并提供“重试保存”。

导入备份会等待已接收的写入完成，校验路径、编码和 JSON，再写入临时目录。替换失败会恢复原目录；成功后，原数据保留在用户数据目录旁的 `ai-agent.previous-<UUID>` 目录。导入后需要重启，期间阻止旧运行状态覆盖恢复数据。正在执行聊天或后台任务时不能导入。

聊天和后台任务共用工具确认队列。需要确认却没有确认入口时拒绝执行；任务取消会中断模型请求、网络工具请求，并移除待确认弹窗。取消状态不会被迟到的响应覆盖。工具超时同样会发送中断信号；已经完成的文件操作不会被自动撤销。

设置按页面独立加载，各资源分别超时、显示错误和重试。重试仅请求失败项，保留其他表单输入；模型配置读取失败期间禁用保存，避免将默认值覆盖到已有设置。

## 本地检查

```sh
npm run typecheck
npm run test:system
npm run test:model-settings
npm run evals
npm run build
```

`test:system` 在系统临时目录中运行真实存储逻辑，通过受控故障模拟验证写入失败、备份回滚、取消、确认队列及设置加载；不读取实际用户数据。

`evals` 运行生产路由和 Agent 工具分发，并检查实际 RAG 请求的上下文、引用提示和历史隔离。模型和外部 I/O 使用模拟返回，不代表真实模型的回答质量或线上接口可用性。
